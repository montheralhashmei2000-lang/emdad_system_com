## القرار المعماري الأول: إلغاء المزامنة (نظام أونلاين فقط)

طلبك اعتماد نظام عمل على الإنترنت فقط يحلّ جذر أخطر مشاكل الفحص دفعة واحدة:

| نقطة الفحص | كانت | صارت |
|---|---|---|
| **1 (P0 حرجة)** `/sync/push` يتجاوز RBAC بالكامل | أي مستخدم مسجَّل يكتب أي جدول عبر المزامنة | **المسار محووف نهائيًا** — لا يوجد `/sync/*` إطلاقًا، فلا يوجد باب لتجاوز الصلاحيات. كل كتابة تمر عبر راوتر API مشروط بـ `require_permission(...)` |
| **2 (P0)** العميل يتحكم بـ `updated_at`/`deleted`/`device_id` | سببها منطق المزامنة | أُلغيت مع المزامنة — الخادم وحده يضبط هذه الحقول عبر `SyncMixin` |
| **5 (P0)** فقدان التغييرات المتعارضة من Outbox | `setOutbox([])` حتى مع conflicts | أُلغي الـOutbox كليًا — كل عملية كتابة تُحفظ فورًا على الخادم أو تفشل برسالة واضحة |
| **6 (P1)** Race condition في طابور Outbox | كتابات متوازية تمحو بعضها | أُلغي مع الطابور |
| **7 (P1)** نافذة فقدان بين القراءة والـcursor | `server_time` بعد القراءة | أُلغيت مع الـpull |
| **29 (P2)** لا Idempotency في المزامنة | تكرار العمليات عند retry | أُلغيت مع المزامنة |

نتيجة حاسمة: اختبار `test_sync_endpoints_removed` يتحقق أن `/sync/push` و`/sync/pull` يعيدان **404** حتى لمستخدم admin.

## ما يتطلبه منك قبل التشغيل الفعلي (خطوات لا يمكن لأحد تنفيذها عنك)

1. **إلغاء مفتاح Firebase Service Account القديم** من Firebase Console (اعتبره مكشوفًا) وإنشاء مفتاح جديد خارج المشروع.
2. إنشاء `SECRET_KEY` و`FIELD_ENCRYPTION_KEY` جديدين في `.env` للخادم (الأمثلة في `.env.example`).
3. تعيين كلمة مرور أولية قوية للمدير: `INITIAL_ADMIN_PASSWORD=... python seed.py`.
4. بناء APK بإصدار موقّع: إنشاء keystore + `key.properties` (قالب `key.properties.example`) ثم:
   `flutter build apk --release --dart-define=API_BASE_URL=https://خادمك --dart-define=APP_ENV=production`
