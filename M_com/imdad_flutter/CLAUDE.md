# CLAUDE.md - Project Constitution & AI Guidelines

> Last audited: 2026-10-09 (second pass that day: sync / backup-on-mobile / per-document print templates) against the working tree (v8.0.1+801, schema v25). Every number below was measured then; re-measure before quoting.

## 1. Project Overview
- **Name:** Supply Chain & Inventory Management System (نظام الإمداد والتموين). Native app, **offline-first**, Android (APK) + Windows (EXE). Web is NOT a target.
- **Language:** Arabic (RTL). All UI text Arabic; code comments English for complex logic.
- **Goal:** Premium-ERP look and speed (Onyx Pro class), dense on desktop, usable one-handed on mobile.
- **Size (measured 2026-10-09):** 330 hand-written Dart files in `lib/` (93.3k lines incl. blanks + 57k generated `app_database.g.dart`), 137 files in `features/` (69 `*Screen` classes), 55 Drift tables (10 files under `tables/` + `linkage_tables` 11, `archive_tables` 1, `cable_tables` 1), `kSchemaVersion = 25` (`lib/data/db/app_database.dart:103`), 149 test files, `flutter analyze` clean. **Analyze is not 12 s:** 246 s cold (first run of a session, measured 2026-10-09), then 3–50 s warm or scoped to a folder — budget for the first one.
- **Two sections only:** Supply (`AppSpace.supply`, "الإمداد والتموين" — supply and rations are ONE section) and Fuel (`AppSpace.fuel`). There is no separate "Tamween" section (`lib/domain/app_space.dart`).

## 2. Mandatory Workflow Rules
- **Build:** `*.g.dart` are NOT committed. After clone/pull or any change under `lib/data/db/` tables run `dart run build_runner build --delete-conflicting-outputs`. Without it nothing compiles.
- **Before finishing any change:** `flutter analyze` must be clean; run the affected test files (`flutter test test/<file>`). Full `flutter test` takes ~14 min (14m23s measured 2026-10-09); run it once at the end, never in parallel with analyze. Slowest (>30 s each, PBKDF2/login + 360×740 layout sweep): `password_upgrade`/`login_password_upgrade` cases and `mobile_layout_test` phone sweeps.
- **Never** edit `ci.yml`, `*.g.dart`, or `OwnerKey.publicKey` unless explicitly asked. The workflow lives at the REPO ROOT (`D:\Emdad_Repository\.github\workflows\ci.yml`, `working-directory: M_com/imdad_flutter`), not inside this folder. CI = analyze + test (Ubuntu, 45 min cap), `build apk --release --obfuscate` (throwaway key), `build windows --release` (Flutter pinned 3.47.4).
- **Commits/push only when asked.** Confirm the exact target file path before editing. If a change breaks build/lints, revert it and try another approach. Refactor screens incrementally.
- New `Imd*` behavior that changes an existing widget must stay backward compatible. Improve an existing component before adding a parallel one.
- Schema change ⇒ bump `kSchemaVersion`, add an `if (from < N)` block in `onUpgrade` (`app_database.dart:396+`), add a migration test (see `test/migration_v25_test.dart`).

## 3. Architecture
Layers (dependency flows downward only): `core/` (security, theme, UI kit, print, export) → `data/` (db, repos, sync, migration, backup, ocr) → `domain/` (pure rules; **no Flutter** — that part holds, but four files do import `data/`/`core/`, see §8 item 38) → `features/<area>/` (screens). `main.dart` wires `AppDatabase`, `AuthService`, `AutoSyncService`, `IdleLock`, `BackupScheduler`, `ImdTheme` via `provider` **as DI only**; screen state is `setState`. Do NOT add Riverpod/Bloc/GetX.
- **Data flow:** Screen → `*Repo(db)` (`lib/data/repos/`) → Drift (`AppDatabase`, SQLCipher, WAL) → SQLite triggers (qty guards, item delete guard). Stock balances: `MovementsRepo._balanceRows()` (SQL `SUM/GROUP BY`, `movements_repo.dart:215`) is the source of truth; `StockLedger` (`domain/stock_ledger.dart`) is the in-memory twin and must stay equivalent (`test/balances_sql_test.dart`). Inactive statuses: `DRAFT, ORDER, CANCELLED, REJECTED`.
- Screens should call repos, not Drift directly. Known violations: items/issue/receive/transfer/warehouses/dashboard/insights screens (see §8). Do not add new ones.
- Key files per area:
  - Auth/permissions: `core/security/{auth_service,perm,warehouse_scope}.dart`, `domain/{access_control,perm_catalog,menu_doors,section_block}.dart`.
  - Crypto/owner: `core/security/{pbkdf2,password_hash,owner_key,owner_signature,device_activation,esign,owner_promotion}.dart`, `data/db/db_cipher.dart`, `data/migration/backup_crypto.dart`.
  - DB: `data/db/{app_database,tables/*,linkage_tables,archive_tables,cable_tables,pre_migration_backup}.dart`.
  - Sync: `data/sync/{lan_sync,sync_crypto,sync_trust,sync_marks,auto_sync}.dart`, `data/migration/legacy_import.dart` (merge entry point `importJson`). Trust has two buckets (`SyncTrust.accepted` = whose signed requests we answer, `peers` = whose door we knock on); pairing writes **both** on both devices and `SyncTrust.mirror()` repairs older one-sided rows (§8 item 30). `AutoSyncService` owns the single port: `pause()` stops cycles only, `releasePort()/reclaimPort()` hand it to manual pairing, `listening` says whether it is open.
  - Printing: `domain/print_forms.dart` (the catalog) + `SettingsRepo.printLayoutFor` — see §5 «Printed forms».
  - Excel templates: `data/migration/excel_templates/` (7 templates: items, units, entitlements, camp strength, opening balances, stocktake count, fuel allocations) behind `ExcelTemplates`; UI `features/excel_templates/excel_templates_dialog.dart` (`ExcelTemplatesButton` in each of the seven screens' `ImdPageTitle.actions`). See §5 «Excel templates».
  - Stock: `data/repos/movements_repo.dart`, `domain/{stock_ledger,issue_rules,unit_carry}.dart`.
  - Shell: `features/home/home_shell.dart` + `shell/*` (sidebar, topbar, bottom nav, menu tree `_menu`).
  - UI kit: `core/ui/**` (tokens `imd_tokens.dart`, table `widgets/imd_table.dart`, fields `widgets/imd_fields.dart`, `imd_form.dart`, `imd_page_chrome.dart`).
  - Print/export: `core/print/*` (pdf), `core/export/excel_export.dart`, `data/migration/{excel_import,xlsx_reader}.dart`.
  - Global search (Ctrl+K): `data/search/search_service.dart` + `features/search/search_modal.dart`. Each scanned table declares its `page` **and** its `perm`; when the page has its own `PermCatalog` entry the two must be identical — `search_perm_test` enforces it, after `link_persons` was found guarded by `linkages` while its screen is guarded by `personnel`. The modal debounces 300 ms and drops out-of-order results by sequence number.

## 4. Security Invariants (do not weaken)
- Passwords: PBKDF2-HMAC-SHA256, 310,000 iterations (legacy 45,000 re-hashed on login); lockout 5 tries/3 min per lowercase username; session 12 h and cleared on exit; min length 8; idle lock (`IdleLock`).
- DB: SQLCipher, key in `flutter_secure_storage` (`imdad.db.key`). Backups: `IMDBK2` AES-256-GCM. LAN sync: ECDH + HMAC-signed requests + AES-GCM payload, ±5 min timestamp, nonce replay set; pairing code 8 chars/10 min.
- Owner key: public key is embedded in `OwnerKey.publicKey`; private key lives only on the master device. Release builds throw if it is empty (`main.dart:43`). Device activation tokens and privileged-user rows are ECDSA P-256 signed.
- **Section blocking (v25):** `users.section_blocked` (`supply`, `fuel`, `admin.settings|users|audit|sync|devices`); fail-closed (corrupt JSON ⇒ all blocked); checked on the ORIGINAL page id in `AccessControl.can`, `Perm.has`, `AuthService.can`, `home_shell._hasPerm`. Owner never blocked.
- **Sync guard:** `LegacyImporter._userRejection` rejects (audit `sync.role_rejected`, high) a synced user row that raises role to admin/owner, **lowers the role of a locally privileged row**, or removes a block without a valid owner signature; and a non-privileged row carrying the username of a different-id privileged account (kind `username`). Tombstones are guarded too (`_tombstoneRejection`, audit `sync.tombstone_rejected`, one row per payload): a locally privileged user or a `localOnlyKeys` setting is never deleted by sync, and `audit_logs` tombstones are ignored silently (peers' own pruning sends them legitimately). Synced audit rows are `insertOrIgnore` — never rewritten. Rejected rows/tombstones keep their local sync mark (`_rejectedMarks`). Deleting an admin is a two-step retire (`UsersRepo.deleteUser`, §10) (`users.owner_sig` JSON `{"r","s"}`; digests in `OwnerSignature`, `updatedAt` in Unix SECONDS). Any code that changes a privileged user's row must call `UsersRepo.resign(id)` afterwards. Existing admin/owner rows are also protected: a synced change to salt/hash, `permissions`, `warehouseScope`, `active` or `approved` needs a valid owner signature `c` (`OwnerSignature.credsDigest`, signed by `UsersRepo.resign`, rejection kind `credentials`). After upgrading, the owner must run `UsersRepo.signPrivilegedUsers` once so existing admin rows carry `c`; until then their credential changes are rejected on other devices. Admin password changes made on a non-owner device do not propagate (by design).
- **Trust direction (changed 2026-10-09):** a permanent peer key is now stored in both `accepted` and `peers` on both devices, so either side may start a cycle and either side opens its port to the other. The key is the one derived from the human-entered pairing code (`SyncSession.trustKeyFor`), identical on both sides since the first release — no new secret and no new reachable party. `SyncTrust.forget` still clears both buckets.
- File restore (`importFile`) is trusted (`sys.backup`) and audited `backup.restore`. Pre-migration backup `imdad.sqlite.pre-v25-<ts>` kept 7 days.
- Audit: `AuditRepo`; risks `high/sensitive/critical` are never pruned (`protectedRisks`), normal TTL 730 days. The log is not hash-chained.
- Drafts must not hold sensitive data in `SharedPreferences` (plain file). The issue-screen recovery draft lives in the encrypted DB (`SettingsRepo.readIssueRecovery`, local-only key `issueRecovery`); the old prefs key is migrated and wiped on first restore.

## 5. UI/UX Rules (CRITICAL)
**Theme & tokens**
- Light/Dark/System. NEVER hardcode colors: use `context.imd.xxx` (`ImdColors`, `imd_tokens.dart`) or `Theme.of(context).colorScheme`. Emerald `#047857` light / `#10B981` dark. **Both sections share that palette by default**; the fuel orange (`ImdColors.fuelLight/fuelDark`, `AppTheme.fuelSection`) is opt-in via `ImdSectionTheme.distinctFuel` (Settings ▸ المظهر والعرض) — `home_shell._themeFor` returns the base theme unless it is on. PDF code may use `PdfColors`; barcode/QR painters may use fixed black/white via `ImdFixedColors`. `test/design_rules_test.dart` enforces both color and fixed-width rules — keep it green.
- Font: bundled `IBMPlexSansArabic` (`ImdSizes.font`); user-selectable families live in `ImdFonts`. No `google_fonts`.
- Radius/padding/heights come from `ImdSizes`/`ImdDensity` getters (they follow Classic style and High-Density). Never hardcode a radius that should follow them. Cards radius `ImdSizes.radius` (12; 2 in classic).

**Breakpoints (actual, not aspirational)**
- `ImdBp.mobileMax = 900` (`imd_tokens.dart:512`): `mobile` ⇒ ≤900, `wide` ≥1200, `tiny` ≤420. Used by tables, KPIs, pages.
- The shell has its own thresholds (`_Shell`, `home_shell.dart:111`): handheld ≤900 (endDrawer + `_BottomNav`, single page), 900–1150 icon rail (68px), >1150 full sidebar (default 290, drag-resizable 220–420, persisted `imdad.sideWidth`). Do not add a fourth threshold.
- Never use fixed widths for layout. Use `ImdFit(width:)` (shrinks to available), `LayoutBuilder`, `Expanded/Flexible`. Known tolerated fixed widths: unit cell `SizedBox(width: 104)` in entry rows, 280 settings/report nav panes.

**Shell (desktop)**
- Pages open as MDI tabs (`ImdPageTabs`, max 8 per section), kept alive by `ImdPageHost` (Offstage+TickerMode+ExcludeFocus). Both sections stay mounted when switching (`_SpaceState`; `test/section_switch_test.dart`). A hidden page whose data changed is flagged stale (orange dot + `ImdStaleBanner`), never auto-reloaded. Screens are NOT pushed as routes; full-screen `Navigator.push` is reserved for editors/scanner (items barcode, contract/custody editors, device activation, `ImdScan`). Dialogs/sheets: `showImdModal`.
- **One top bar (desktop):** `_DesktopBar` (`shell/home_shell_topbar.dart`) is a single 40px row (`ImdSizes.desktopBarHeight`) under the NATIVE Windows title bar (kept for Snap + Mica): sidebar collapse button (☰) → page tabs (`ImdPageTabs(embedded: true)`, max 150px each, the home page `dash` has no tab) → `ImdMenuBar` (ملف/مساعدة, only >1180px) → section switcher → theme → bell → user chip. Controls use `dense` variants (28px). There is no brand text, no «IAM محمي» pill, no separate tab strip. Handheld (≤900) keeps `_Topbar` (burger + title). Do not add a second bar row.
- **Window (Windows):** the main window keeps the native title bar (`TitleBarStyle.normal`, app name at its edge) so Snap Layouts and Mica work; only the login card is frameless. A custom frameless title bar was tried and reverted.
- **Sidebar collapse:** the ☰ button toggles an icon rail (`imdad.sideCollapsed`, `null` = auto: rail between 900–1150px). The rail shows Home + the **main section icons only** (`_RailSection`); tapping one opens a flyout menu of its pages. Spaces with a single section show their pages flat.
- Status bar (`ImdStatusBar`, desktop only): clock, sync state (from `AutoSyncService`), record count (`ImdRecordScope`), density + classic toggles. Android back: closes drawer → goes home → confirm exit (`PopScope`). Windows close button is intercepted and confirmed.
- Shortcuts (desktop only, `ImdShortcuts.supported`): Ctrl+S save, Ctrl+P print, Ctrl+N new, F5 refresh, Enter confirms dialogs, Esc closes pickers only (no global Esc).

**Settings screen navigation**
- Desktop: a 280px vertical pane, grouped with headers (`_groups`). Mobile (≤900): the same sections as one `ImdSelect` picker labelled «القسم — المجموعة», **not** a horizontal chip strip — sixteen chips in one scrolling row hid everything past the sixth (§8 item 33). A section added to `_sections` appears in both automatically; add it to `settings_sections_test` too.
- A section whose content is owner-only (`sys.*`) must say so in place (`«👁 … للمالك وحده»`) rather than render an empty panel — an empty panel reads as a missing feature, which is exactly how the backup section looked to a branch admin.

**How to build a new screen**
1. Add the page id to `_menu` (`shell/home_shell_menu.dart`), `_pageBody` switch (`home_shell.dart`), a permission in `PermCatalog`, and its section in `AppSpace.pages`. A page that is a sub-section of another (e.g. Settings sections) is wrapped in `ImdEmbedScope` and gets no sidebar item.
2. Layout: `ImdPage(children: [ImdPageTitle(...), ImdICard(...), ImdChipsRow(...), ImdTable(...)])`; entry/voucher screens use `ImdStickyPage` (sticky scanner/header + sticky footer with Save/Approve/Print). Page-header tabs/actions go through `ImdPageTitle.actions`.
3. Tables: read tables use `ImdTable` with `pageSize: 50` (house standard; 100 for light rows) and `values:` (raw cells) on large read tables to enable Find/filter/group/count. Only 9 screens do today (items, suppliers, balances, dashboard, doc log, fuel ledger, camp ledger, reports center, stock alerts; of 82 `ImdTable(` call sites, 72 pass `pageSize` (measured 2026-10-09)) — add it to movement/ledger tables you touch. `onRowTap/rowMenu/rowColor` receive the ORIGINAL row index. Item-entry tables (receive, issue, transfer, returns, opening, ration order, stocktake) MUST use `ImdEntryTable` (flush cells, row = `ImdSizes.compactField`). Dropdown + quick-add ⇒ `ImdInputGroup`. On mobile tables stay tables (natural width, horizontal scroll, `freezeFirst`) unless they pass `cards: true`, which is enabled on 5 catalog screens: items, warehouses, suppliers, units (issue history), authorities. `ImdTable` renders cards at width ≤900 and ignores `maxHeight`/`freezeFirst`/`minWidth` in cards mode.
3b. **Mobile entry rows:** the four voucher screens (issue/receive/transfer/returns) render their phone layout through `ImdEntryRowGrid` (`doc_kit/imd_form_layout.dart`) — item + unit + qty in one row when width allows, else the item drops to its own row and unit stays beside qty; `extras` go to a third row and `actions` align to the fields, not the labels. Each screen used to hand-roll the same grid, and all four put the quantity alone on a row away from its unit. Add a field by passing it to the grid, not by rebuilding the layout.
4. Fields: `ImdFld`/`ImdField` (`required` adds red `*`; `errorText`), `ImdSelect` (large searchable dialog, never a small dropdown), `ImdDateField` (picker only, stores `YYYY-MM-DD`, range 2000–2100), numbers via `number: true`. Pre-save validation uses `ImdValidationBox`/`ImdCheck` lists.
5. Feedback: `showImdToast(context, '✔ …')` / `error: true` (SnackBar based). No `AlertDialog` for success; confirmations via `imdConfirm`. Loading: first load of a table/dashboard screen uses `ImdShimmerTable`/`ImdShimmerKpis` (`imd_shimmer.dart`; balances, document log, suppliers, dashboards do). `ImdLd` (text) is the accepted loader for small inline/tab panels, forms and computed-on-demand outputs (~93 uses) — do not mass-migrate it; convert only when a screen's main table is loading.
6. After every `await`, guard `context`/`setState` with `mounted`.
7. Exports: `ExcelExport.build/writeToFile` (strings; mark numeric columns); printing via `DocumentPdf`/`PrintDoc` + `showPrintPreview`. **The layout always comes from `SettingsRepo.printLayoutFor(PrintForms.<key>)`, never `printLayout()` and never the `PrintLayout.defaults` default argument** — see «Printed forms» below. `thermal_print.dart` exists but has **zero callers**; it is not a wired path.
8. Add the page id to `test/mobile_layout_test.dart` (sweeps 320/360/740-landscape/800 at 1.3 text scale; text scale clamped by `kImdMaxTextScale`).

**Printed forms (per-document templates)**
- Every printable document has a key in `PrintForms` (`lib/domain/print_forms.dart`): 34 entries across both sections, grouped سندات المخزن / تقارير وكشوف / المحروقات / الارتباطات والمالية / البرقيات والوثائق. The catalog is also the attendance list — `print_forms_test` fails on a `PrintForms.x` used in code but absent from it.
- Storage: the **synced** `printForms` key holds `{formKey: layoutMap}` overrides; `printLayout` keeps the global default. `SettingsRepo.printLayoutFor(key)` returns the override if the form was given its own design, else the global one (unknown key ⇒ global, so a removed key never breaks printing). Helpers: `savePrintLayoutFor`, `clearPrintLayoutFor`, `customizedPrintForms`.
- `VoucherPrint.print` picks the key from the voucher kind (`VoucherPrint.formOf`); `engineOf(db, form:)` is how the `MilitaryPrint` engines (cable/contract/custody/receipt) get theirs.
- Settings ▸ «رأس وتذييل النماذج» (`FormsDesignerScreen`) edits **one** form at a time: the sticky bar's «المطبوعة» picker selects the global default or any catalog entry (● marks the customized ones), and `_scopeNote()` states in words what the Save button will touch. A form follows the global default until «إفراد هذه المطبوعة بتصميم» is pressed.
- Adding a printable document: add a `PrintForms` entry **and** pass its key at the print site. `print_forms_test` has a second test that fails any `DocumentPdf.printDoc/share/build` call in `features/` with no `layout:` argument (it scans by balanced parens, so `layout:` after a long `doc:` still counts).

**Excel templates (import / export)**
- Four templates, each an `.xlsx` with two sheets — «البيانات» (Latin digits) and «التعليمات» (Arabic digits): الأصناف (10 columns, up to 3 units, unit 1 is the base with factor 1, column J → `Items.reportUnit`), الوحدات المستفيدة (code builds the tree: no «-» ⇒ root `type=camp`, «a-b» ⇒ child of `a`, two levels only, اختصاص from five values), الاستحقاق (item by code, name only verifies, unit must be one of the item's units), تفريدة المعسكر (camp + date are chosen in the import dialog, not in the file).
- **Detection** is by header row (`TemplateTable.detect`, `TemplateSpec.detectKeys`); a file matching none is refused. **Reading goes through `XlsxReader`**, never `Excel.decodeBytes` (the package throws on Arabic Excel files); writing uses the `excel` package directly because `ExcelExport` is one sheet with no formulas.
- **Two phases, one code path:** `run(dryRun: true)` validates every row and returns a `TemplateReport` without writing; the dialog shows it (ناجح / فاشل + per-row reasons, حُذف / بقي in replace mode) and only «تنفيذ» runs `dryRun: false` inside one transaction. A failing row never stops the file. Merge = add/update; replace = the file is the reference.
- **Replace is guarded:** needs `Perm.canDelete(page)` (the engine also throws `StateError` without `allowDelete`), is audited `excel.template.import` at risk `high`, refuses when the file has no valid row, and never deletes (a) a record whose row failed (typo ≠ delete), (b) items with movements, (c) units referenced by strengths / issues / transfers / returns / assets / fuel issues / camp ledger, or a root that still has children — those are counted as «بقي».
- **Camp-strength specifics:** «نسبة الزيادة» is the **count** of the increase (so الإجمالي = B + C), `pct` is derived (`C ÷ B × 100`); exported الإجمالي is a real formula `B{n}+C{n}` with `SUM` totals (stored in `<f>` **without** «=»); on import the cached value is compared and a mismatch is a warning, a missing cached value (our own export) just computes B+C. Merge keeps the day's other units; replace swaps that camp+day only. Rows of the other mode (camp-total vs per-unit) are removed in merge with a warning.
- Entitlements have two import paths (this and `ExcelImporter`'s «نسب الاستحقاق» sheet) — left as is, `TODO(excel-templates)` in `excel_templates.dart`.
- **Templates 5–7 (phase 2):** (5) الأرصدة الافتتاحية — warehouse + date chosen in the dialog; quantity = Σ(qty × unit factor) stored in the item's **base** unit; goes through `CatalogRepo.setOpeningBalances` (delete-then-insert per item/warehouse, i.e. it replaces, never adds) with the screen's per-item `OPENING_BALANCE_SET` audit at `critical`. Replace also clears openings not in the file, **except** an item with a live receipt/issue/return/adjustment/transfer in that warehouse (DRAFT/ORDER/CANCELLED/REJECTED ignored) — deleting its opening would leave a negative balance — counted «بقي». (6) العد الفعلي — open stocktake order chosen in the dialog; **merge only** (the screen has no replace, so none here); every row goes through `StocktakeRepo.saveCount` with the screen's rules: order must be `COUNTING`, only the 3 largest units (`unitsDescending.take(3)`), an already-counted line needs `stocktake.edit` (`canEditCounted`), a count identical to the recorded one is skipped («بلا تغيير»), and an item not in the order is **rejected** (adding it is an explicit act in the screen). It never touches balances; `approve()` still writes the adjustments. (7) تفريدة المحروقات — works on `FuelUnits` (a separate directory from `BeneficiaryUnits`) and `FuelAllocations`; fuel type + start date chosen in the dialog; saved only through `FuelRepo.saveAllocation`/`deleteAllocation` (so its audit and `تف-` numbering apply); matching: code ⇒ code only then the name must agree, empty code ⇒ by name, unknown/ambiguous/inactive ⇒ row rejected; `monthly = typed > 0 ? typed : round(weekly × 4)`; location required (the screen's «جميع المعسكرات» default is NOT applied); an update keeps the allocation's `refNo`, start/end date, active/disbursable and notes (the dialog's date is for new ones only); two allocations for one (unit, type) ⇒ the row is refused, not guessed; replace deletes the type's allocations not in the file via `deleteAllocation` (issued-against ones stay).
- **Detection:** templates 5 and 6 have **identical headers**, and items' detect keys are a subset of theirs. `TemplateTable.detectAll()` returns every match and drops a template whose keys are a strict subset of another match; the ambiguity left (5 vs 6) is resolved by the screen that opened the dialog (`expected`), and a file opened from an unrelated screen is refused with that explanation. `detect()` returns a kind only when unambiguous.
- Permissions are per detected kind (dialog `_exportAction/_canImport`): opening import = `opening.create` + warehouse scope (`perm.scope`), export = `view`; stocktake import = `create` or `edit`; fuel allocations export = `view`, import = `edit`, replace = `canDelete` (catalog untouched — it has no export/import actions). Replace on `opening` is therefore admin/owner only (no `delete` action there).
- Adding a template: `TemplateKind` + `TemplateSpec`, an engine file with `exportRows`/`run`, wire both switches in `ExcelTemplates`, a test file per template, and a button in the screen.

**Numbers:** `nf()`/`nfMoney()` (screens) and `printNum()`/`printMoney()`/`printDate()` (print+export) all read `ImdNumbers.current` — digit shape (Arabic-Indic/Latin, separately for screens and print), thousands and decimal separators, quantity decimals (trimmed) and money decimals (fixed). Stored under the **synced** `numbers` key (`SettingsRepo.numbers/saveNumbers/loadNumbers`), loaded in `main`, edited in Settings ▸ «الأرقام والعملات». Never hardcode a digit shape or a `NumberFormat` — add the knob there instead. Defaults are unchanged: screens Arabic-Indic, print Latin, `,`/`.`, 3 qty decimals, 2 money decimals.

**Density & style:** `ImdDensity` (high density; touch targets never shrink), `ImdStyle` (classic flat: radius 2, Tahoma, `ImdColors.classicLight`) and `ImdSectionTheme` (fuel palette on/off) are static switches applied by `ImdDensity.rebuildAll`, all three surfaced in Settings ▸ «المظهر والعرض» (they used to live in the desktop status bar only, so Android could not reach them). `ImdBp.touch` (Android/iOS) ⇒ touch min 46, field 40.

## 6. Cross-Platform Rules
- Must build for Android and Windows. `Platform.isWindows/isAndroid` only when unavoidable (window manager, Mica, file paths, scanner/OCR; OCR via Tesseract is Android-only). Packages must support both.
- Android release: R8 on, signing guard in `build.gradle.kts` refuses debug key; `allowBackup=false`. Camera, biometric, multicast permissions declared.
